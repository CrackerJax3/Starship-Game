  3. BUILD — SIGNED RELEASE APK / AAB
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[ ] Create a keystore file (DO THIS ONCE — keep it safe forever)
    Run in terminal:
      keytool -genkey -v -keystore starship-release.jks \
        -alias starship -keyalg RSA -keysize 2048 -validity 10000

    Store the keystore file and passwords somewhere very safe.
    Losing it means you can never update the app on the same listing.

[ ] Configure signing in android/app/build.gradle:
    Add under android { ... }:

      signingConfigs {
          release {
              storeFile file('path/to/starship-release.jks')
              storePassword 'YOUR_STORE_PASSWORD'
              keyAlias 'starship'
              keyPassword 'YOUR_KEY_PASSWORD'
          }
      }
      buildTypes {
          release {
              signingConfig signingConfigs.release
          }
      }

[ ] Build the release AAB (preferred over APK for Play Store):
      cd android && ./gradlew bundleRelease

    Output: android/app/build/outputs/bundle/release/app-release.aab

[ ] Or build signed APK:
      cd android && ./gradlew assembleRelease

Google requires a privacy policy because your app:
  - Uses Google AdMob (collects advertising data)
  - Requests AD_ID permission
  - Submits player names and scores to Firebase

[ ] Host a privacy policy at a public URL (options):
    - Create a free page at https://www.privacypolicygenerator.info
    - Or use https://app.privacypolicies.com
    - Or host a simple HTML file on GitHub Pages

[ ] Your privacy policy MUST mention:
    - What data you collect (player name, score, device ad ID)
    - Why you collect it (leaderboard, advertising)
    - Third-party services used:
        * Google AdMob: https://policies.google.com/privacy
        * Google Firebase: https://firebase.google.com/support/privacy
    - How users can request data deletion (provide your email)
    - That you do not sell personal data
    - Children's data section (see Section 6 below)

[ ] Enter the privacy policy URL in the Play Console under:
    App content → Privacy policy

  6. CHILDREN & FAMILIES POLICY (IMPORTANT — read carefully)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Because your app is rated Everyone and may appeal to children:

[ ] Decide: is this app directed at children under 13?

    OPTION A — NOT directed at children (recommended for you):
    - In Play Console: App content → Target audience → select "13 and over"
    - You must still have a privacy policy
    - AdMob will serve standard (non-child-directed) ads
    - Easier path, fewer restrictions

    OPTION B — Directed at children / Designed for Families program:
    - Far more restrictive ad requirements (no behavioural ads)
    - Must use only pre-approved ad SDKs
    - Much harder to monetise — avoid this unless the app is
      specifically designed for young children

    RECOMMENDATION: Select "13 and over" as your target audience.
    The game content (rocket science, leaderboard, controls) is
    naturally suited for teens and adults.
